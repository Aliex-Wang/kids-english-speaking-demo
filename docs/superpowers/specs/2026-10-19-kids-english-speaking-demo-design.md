# 少儿英语口语对话练习 Demo 设计

- 日期：2026-10-19
- 状态：设计已更新，待用户审阅
- 产品阶段：可试用 Demo
- 技术路线：Python-first Web/PWA

## 1. 背景与目标

### 1.1 产品定位

面向 4–12 岁儿童的英语口语对话练习应用。孩子在家中使用平板或电脑浏览器，在家长帮助下选择难度，通过卡通角色和日常场景完成短对话练习。

首版不追求完整课程体系，而是验证两个核心假设：

1. 孩子是否愿意主动按麦克风并连续说 5 轮以上。
2. 三档难度是否能帮助不同年龄段的孩子完成场景目标表达。

### 1.2 Demo 目标

- 单次练习 5–8 分钟。
- 每次练习由系统从生活主题库自动生成一个场景，并适配三档参数化难度。
- 回合制语音对话：孩子说话，AI 识别后回应。
- 以“敢开口 + 会用场景表达”为首要目标。
- 不登录、不做家长后台；Demo 不做发音评分，V1.1 必须实现。

### 1.3 非目标

以下能力不在 Demo 范围内：

- 账号、短信登录、跨设备同步。
- 家长端和教师端。
- 发音评分与纠音训练。
- 内容管理后台。
- 大规模课程体系和教材同步。
- 全双工实时语音。
- 支付、会员和运营系统。

## 2. 目标用户与使用场景

### 2.1 用户

- 主要用户：4–12 岁儿童。
- 辅助用户：家长，帮助孩子选择难度；场景由系统自动生成。
- 使用地点：家庭。
- 主要设备：平板或电脑浏览器。
- 网络要求：在线使用，中国大陆可稳定访问。

### 2.2 难度分层

| 难度 | 目标年龄 | 回答方式 | 对话轮数 | 辅助 |
|---|---|---|---|---|
| Sprout | 4–6 岁 | 单词或 1–3 个词 | 4–5 轮 | 中文提示、慢速语音 |
| Explorer | 7–9 岁 | 简单短句 | 5–6 轮 | 句型开头提示 |
| Star | 10–12 岁 | 完整句子 | 6–7 轮 | 少量自由表达 |

## 3. 产品范围

### 3.1 动态生活场景

Demo 不固定具体场景。每次开始练习时，系统根据难度从生活主题库中自动生成一个完整场景，孩子不需要输入场景描述。

生活主题库覆盖：

- 家庭日常：早餐、整理书包、睡前准备。
- 学校生活：教室、操场、图书馆。
- 购物：超市、面包店、宠物店。
- 饮食：餐厅、水果店、零食时间。
- 出行：公交、公园、动物园。
- 朋友与社交：认识新朋友、生日会、一起玩。

每个生成场景必须包含：

- 一个孩子熟悉的日常生活任务。
- 一个明确角色和对话目标。
- 4–7 个对话步骤。
- 符合当前难度的目标表达。
- 至少 1 轮自由表达。
- 安全、非商业化、不索取个人信息的内容。

系统会避开最近两次练习使用过的主题。场景插画按生活主题使用 6 套通用素材，不为每个生成场景实时生成图片。

生成失败时使用经过人工审查的安全保底场景；保底场景仅作为故障降级，不进入正常场景池。

### 3.2 页面流程

```text
开始页
  ↓
选择难度与卡通头像
  ↓
自动生成生活场景（短暂加载）
  ↓
任务介绍：听角色说明目标 + 听一句示范
  ↓
对话页：4–7 个回合
  ↓
结束页：星星、目标句型、再练一次
```

### 3.3 对话页布局

- 上方：主题插画、角色头像、当前进度。
- 中间：角色英文气泡，可点击“再听一次”或“慢速播放”。
- 下方：大号麦克风按钮，显示“录音中 / 识别中 / 轮到你了”。
- 辅助区：“帮帮我”按钮，播放参考答案后让孩子跟说。
- 中文只用于必要提示，避免文字过多。

### 3.4 交互原则

- 语音优先，文字辅助。
- 不显示红色错误标记。
- 不要求孩子重复到“满分”才能继续。
- 每次回答后先给积极反馈，再自然示范更完整的说法。
- 单次录音最长 15 秒，Sprout 为 10 秒。
- 不用长时间动画或复杂菜单打断对话。

## 4. 对话设计

### 4.1 场景状态机

场景由后端生成后，形成一条固定的任务链。通义千问只在当前步骤内生成自然回应，不能改变教学目标、步骤数量和难度。

每个生成场景都必须遵循：

```text
Greeting
  → Task step 1
  → Task step 2
  → ...
  → Free expression
  → Goodbye
```

生成结果示例（仅用于说明，不是固定场景）：

- 在面包店买早餐：问候 → 选食物 → 说喜欢什么 → 自由表达 → 告别。
- 整理书包：问候 → 找物品 → 说物品位置 → 自由表达 → 告别。

### 4.2 场景生成与步骤配置

生成场景由 `SceneSpec` 表示，场景级字段包括：

- `scene_id`：场景唯一标识。
- `theme`：所属生活主题。
- `title`：场景标题。
- `setting`：发生地点。
- `role`：AI 扮演的角色。
- `goal`：本场景的沟通目标。
- `steps`：4–7 个对话步骤。
- `target_expressions`：本场景的核心目标表达。
- `safety_notes`：生成和审核时需要遵守的安全说明。

每个对话步骤包含：

- `step_id`：步骤唯一标识。
- `goal`：本步骤的教学目标。
- `role_prompt`：角色本轮要表达的意思。
- `target_phrases`：可接受的目标短语。
- `accepted_keywords`：低难度下可接受的关键词。
- `hint_en`：英文提示。
- `hint_zh`：中文辅助提示。
- `retry_prompt`：没听清时的重试提示。
- `max_attempts`：最大尝试次数。
- `next_step`：下一步骤。
- `allow_skip`：是否允许跳过。

场景生成流程：

1. 后端根据难度和最近主题选择一个生活主题。
2. 通义千问生成结构化 `SceneSpec`。
3. Pydantic 校验字段、步骤数量、目标表达难度和步骤链。
4. 安全校验器检查是否包含暴力、恐怖、成人、品牌推广或个人信息索取。
5. 校验失败时重新生成，最多尝试两次。
6. 连续失败时使用对应主题的安全保底场景。

主题库和保底模板分别存放于 `backend/app/content/life_themes.yaml` 和 `backend/app/content/fallback_scenes.yaml`，由 Pydantic 模型在启动时校验。生成场景不直接写入 YAML。

### 4.3 三档难度参数

| 配置项 | Sprout | Explorer | Star |
|---|---|---|---|
| 目标回答 | 关键词或短词 | 简单短句 | 完整句子 |
| 语音速度 | 慢速 | 正常偏慢 | 正常 |
| 提示 | 中文 + 首词 | 英文首词 | 仅按需提示 |
| 单轮时长 | 10 秒 | 15 秒 | 15 秒 |
| 自由对话 | 1 轮 | 2 轮 | 2–3 轮 |
| 角色回复长度 | 1 句 | 1–2 句 | 2 句以内 |

### 4.4 表达完成判断

采用“规则匹配 + 模型判断”的混合方式：

1. 检查识别文本中是否出现目标词或可接受短语。
2. 如果没有直接命中，再让模型判断语义是否完成了当前任务。
3. 模型返回固定 JSON，由后端进行结构和安全校验。
4. 校验失败时使用该步骤的预设安全回复。

模型输出结构：

```json
{
  "accepted": true,
  "feedback": "Great! You like blue.",
  "reply": "Blue is a nice color. What do you like to play?",
  "hint": "You can say: I like blue.",
  "next_step": "step_2",
  "stars": 1,
  "safety": "ok"
}
```

后端必须校验：

- 字段是否完整。
- `next_step` 是否存在且属于当前场景。
- 回复长度是否符合难度。
- `safety` 是否为 `ok`。
- 是否出现不合适的话题或个人信息索取。

### 4.5 求助与奖励

孩子点击“帮帮我”后：

1. 播放参考答案。
2. 显示简短提示。
3. 等待孩子再说一次。
4. 继续当前流程，不扣星星。

奖励规则：

- 每完成一次有效开口获得 1 颗星。
- 完成目标表达可获得额外星星。
- 不因说错或求助扣星。
- 结束页展示星星、完成的目标句型和“再练一次”。

### 4.6 隐私与本地进度

本机只保存：

- 当前难度。
- 生成场景的签名快照。
- 已完成步骤。
- 星星数。
- 目标表达完成情况。
- 最近生活主题和最近一次练习时间。

默认不保存原始录音，也不保存自由对话中的完整文本。

## 5. 技术架构

### 5.1 技术栈

- 后端：Python 3.12 + FastAPI + Pydantic。
- 前端：FastAPI 提供 Jinja2 页面 + 原生 HTML/CSS/JavaScript。
- 不使用 Next.js、React 或 Node.js 构建。
- 语音采集：浏览器 `MediaRecorder`。
- ASR：阿里云语音识别服务。
- 对话：通义千问。
- TTS：阿里云语音合成服务。
- 部署：Docker + Uvicorn + Nginx。
- 存储：`localStorage`，Demo 不需要数据库。
- 测试：pytest + Playwright。

### 5.2 组件边界

```text
浏览器
  ├─ 页面与交互
  ├─ 录音与播放
  └─ localStorage
        ↓ HTTP/JSON + 音频
FastAPI 应用
  ├─ 页面路由
  ├─ 场景生成 API
  ├─ 回合 API
  ├─ 场景生成器与状态校验
  ├─ 对话编排器
  ├─ 内容安全过滤
  ├─ 主题库与保底模板
  └─ 服务适配层
        ├─ ASR Provider
        ├─ LLM Provider
        └─ TTS Provider
```

ASR、LLM、TTS 均通过独立适配器调用，避免业务代码绑定具体模型接口。

### 5.3 场景生成与单回合数据流

场景生成：

1. 孩子选择难度。
2. 前端调用 `POST /api/scene`。
3. 后端选择生活主题并调用通义千问生成 `SceneSpec`。
4. 后端完成结构、难度和安全校验。
5. 后端返回场景、签名快照和角色开场语音。
6. 前端保存签名快照并进入任务介绍。

单回合：

1. 孩子按住或点击麦克风，浏览器录音，最长 15 秒。
2. 前端把音频和签名场景快照上传到 `POST /api/turn`。
3. 后端校验签名、音频大小、时长和格式。
4. 后端调用阿里云 ASR 得到英文文本。
5. 对话编排器结合场景、难度、当前步骤和最近对话历史调用通义千问。
6. 后端校验模型返回的 JSON。
7. 后端调用 TTS 生成角色语音。
8. 前端播放语音，同时更新本地进度和星星。

### 5.4 API

- `GET /`：开始页。
- `GET /practice`：练习页面。
- `POST /api/scene`：根据难度生成生活场景，返回签名场景快照。
- `POST /api/turn`：上传本轮录音和签名场景快照，返回识别结果、AI 回复、语音和下一状态。
- `GET /api/health`：健康检查。
- `POST /api/event`：记录匿名事件计数，写入服务端 JSON 行日志，不建立数据库。

### 5.5 会话状态

Demo 不需要服务端数据库。场景生成后，后端返回完整 `SceneSpec` 和 HMAC 签名快照。前端把签名快照、难度、步骤和最近对话摘要保存到 `localStorage`。

服务端不依赖长期会话状态；每次请求携带签名快照，后端验证签名、重新校验场景结构，并根据当前步骤生成下一回合。这样刷新页面不会丢失当前练习，也避免 Demo 引入数据库和账号系统。

### 5.6 音频处理

- 浏览器录音优先使用浏览器支持的音频格式。
- 后端需要将上传音频转换为 ASR 要求的格式，例如 16 kHz 单声道音频。
- 原始音频只用于当次识别，处理完成后删除。
- 服务端限制音频大小和时长，避免滥用。
- 录音需要 HTTPS；本地开发可使用 localhost。

## 6. 安全、隐私与儿童保护

- 不在浏览器端暴露阿里云 API Key。
- 所有模型输出必须经过后端校验。
- 生成场景必须通过 Pydantic 结构校验和安全校验。
- 禁止生成暴力、恐怖、成人、歧视、品牌推广或索取个人信息的内容。
- 场景角色不得要求孩子提供真实姓名、学校、住址、电话或照片。
- 限制模型回复长度和话题范围。
- 孩子输入出现不合适内容时，角色应温和转移话题并回到当前任务。
- 日志不记录原始音频和完整对话文本。
- Demo 只记录匿名事件计数，用于验证完成率、开口轮数和失败率。
- 如后续进入正式产品阶段，需要补充家长同意、隐私政策、数据删除机制和适用地区的儿童隐私合规要求。

## 7. 错误处理与降级

| 场景 | 处理方式 |
|---|---|
| 麦克风权限被拒绝 | 显示设备授权指引，并提供文字输入测试入口 |
| 录音为空或过短 | 提示“再试一次”，不计入正式回合 |
| ASR 识别为空 | 播放短提示，让孩子重说 |
| ASR 置信度低 | 使用提示重试，不直接判定失败 |
| 场景生成失败 | 重新生成一次，仍失败则使用安全保底场景 |
| 生成场景未通过安全校验 | 丢弃该场景并使用安全保底场景 |
| 场景签名校验失败 | 拒绝请求，前端重新生成场景 |
| 模型超时 | 使用当前步骤的预设回复继续流程 |
| 模型 JSON 不合法 | 丢弃模型结果，使用预设回复 |
| TTS 失败 | 显示英文文本，使用浏览器语音作为备用 |
| 网络中断 | 显示重试按钮，保留本地进度 |
| 页面刷新 | 从 localStorage 恢复最近一次练习 |

所有错误提示都应简短、友好，不让孩子感到“做错了”。

## 8. V1.1 发音评分训练

发音评分是 Demo 验证通过后的首要功能，不是可选项。

### 8.1 目标

- 对单词和句子给出可理解的发音评分。
- 标记漏读、错读和重音问题。
- 给出简短、可执行的改进提示。
- 不打断对话流程；评分在角色回应前或回应后以轻量方式展示。
- 保持鼓励式反馈，不制造挫败感。

### 8.2 技术预留

后端定义独立的 `PronunciationProvider` 接口，评分服务与 ASR、LLM、TTS 解耦。

优先评估阿里云发音评测能力；如果对儿童语音的识别和评分效果不足，再接入科大讯飞等专用评测服务。

### 8.3 评分维度

- 单词准确度。
- 句子完整度。
- 漏读和错读。
- 重音和节奏。
- 流利度。
- 总体可理解度。

### 8.4 V1.1 验收标准

- 至少覆盖生活主题库中每个主题的核心目标句。
- 评分结果在 2 秒内返回。
- 每个错误都能对应一个具体提示。
- 孩子可以听标准音、重说一次并看到分数变化。
- 评分失败不影响对话继续进行。

## 9. 测试与验收

### 9.1 自动化测试

- 单元测试：场景生成校验、状态机跳转、难度配置、目标表达判断、模型 JSON 校验。
- 集成测试：使用模拟 ASR、LLM、TTS 响应测试场景生成和完整回合。
- 端到端测试：Playwright 模拟麦克风输入，覆盖至少 6 个生活主题 × 3 档难度的场景生成与完整流程。
- 真实服务冒烟测试：使用测试账号验证阿里云接口和音频格式。
- 内容抽检：人工审查至少 30 个生成场景，检查生活常识、难度和安全。

### 9.2 设备测试

- iPad Safari。
- Android Chrome。
- 桌面 Chrome。
- 不同屏幕尺寸下的响应式布局。

### 9.3 儿童可用性测试

邀请 3–5 名不同年龄段儿童，在家长陪同下观察：

- 是否愿意主动按麦克风。
- 是否能理解角色指令。
- 是否愿意在提示后继续表达。
- 单次练习是否能在 5–8 分钟内完成。
- 是否愿意再次开始练习。

### 9.4 Demo 验收标准

- 至少 6 个生活主题 × 三档难度都能生成并完整走通。
- 生成的场景通过结构、难度和安全校验。
- 同一台设备连续练习时不会连续重复同一生活主题。
- 单次练习控制在 5–8 分钟。
- 孩子每轮可以录音、识别并听到角色回应。
- “帮帮我”后可以继续完成对话。
- 麦克风拒绝、识别为空、模型超时、TTS 失败都有可恢复提示。
- iPad Safari、Android Chrome、桌面 Chrome 基本可用。
- 原始录音不保存。
- API Key 不出现在浏览器端。
- 正常网络下，单回合响应目标不超过 5 秒。

### 9.5 验证指标

Demo 记录匿名事件计数：

- 场景主题、难度、完成状态。
- 场景生成成功率和保底降级率。
- 主动说话轮数。
- “帮帮我”点击次数。
- 求助后是否继续说。
- 是否再次开始练习。
- 技术失败率与平均响应时间。

不记录录音，也不记录孩子说出的完整文本。

## 10. 部署

- FastAPI 使用 Docker 部署到阿里云 ECS。
- Nginx 提供 HTTPS；浏览器录音必须使用 HTTPS。
- 阿里云密钥通过服务端环境变量管理。
- 日志只记录请求 ID、耗时和错误类型，不记录音频内容。
- Demo 阶段优先使用阿里云香港 ECS，以减少域名备案等待时间。
- 如果部署到中国大陆 ECS，需要域名和 ICP 备案。
- 后续正式产品阶段再根据访问量和合规要求调整部署架构。

## 12. 风险与应对

| 风险 | 应对 |
|---|---|
| 儿童语音识别不稳定 | 限制单轮时长，提供重试和提示，保留 ASR Provider 替换能力 |
| 回合延迟过长 | 缓存主题级开场和提示音频，动态回复使用 TTS，显示明确等待状态并设置超时降级 |
| 模型回复不可控 | 使用状态机、结构化 JSON 和后端校验 |
| 儿童隐私风险 | 不保存录音和完整文本，日志脱敏，正式版补充家长同意 |
| 中国大陆部署备案周期 | Demo 优先使用阿里云香港 ECS |
| 浏览器音频差异 | 覆盖 iPad、Android 和桌面 Chrome 测试 |
| 生成场景不稳定或不符合生活常识 | 使用结构化 SceneSpec、Pydantic 校验、内容抽检和安全保底 |
| 场景生成延迟 | 进入练习前预生成，显示准备动画，超时后使用保底场景 |
| 场景重复或不符合年龄 | 避开最近主题，按难度校验句子长度和词汇，人工抽检 |
| 内容质量不足 | 维护生活主题库，人工审查目标句和提示 |
| 发音评分效果不稳定 | V1.1 先做小范围评测，再决定阿里云或讯飞方案 |

## 13. 已锁定决策

- 产品面向家庭自学场景。
- 家长不参与首版练习流程。
- 首版不做账号系统，进度存本机。
- 首版为 Web/PWA，优先平板和电脑浏览器。
- 对话为回合制，不做全双工实时语音。
- 首版使用动态生成生活场景，覆盖至少 6 个生活主题和三档参数化难度；保底模板仅用于生成失败。
- 场景由系统自动生成，孩子不需要输入场景描述。
- 后端使用 Python + FastAPI，前端使用 Jinja2 + 原生 JavaScript。
- 使用阿里云 ASR、通义千问和 TTS。
- 首版不做发音评分，V1.1 必须实现发音评分训练。
- 原始录音不保存，匿名事件计数不包含对话文本。
